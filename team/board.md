# Board — Shelf Transfer Mod (Sons of the Forest)

Source: `team/plan.md` (approved; I1–I5 = its five Invariants, D1–D10 = its Decisions), `team/architecture.md`, the brief (§NN).
Paths below are relative to `mods/ShelfTransfer/` (`Core/` = `ShelfTransfer.Core/`, `Plugin/` = `ShelfTransfer.Plugin/`, `Tests/` = `ShelfTransfer.Core.Tests/`).

## Precondition (not a card): Step 0 pre-flight, User only
Steam set to "update only on launch"; BepInEx be.755 installed and launched once (`BepInEx/interop` exists, `LogOutput.log` shows BepInEx loaded); UnityExplorer_Sons added; throwaway single-player save made; a friend lined up for steps 2 and 6. No card below starts an in-game leg until this is confirmed.

## How to read a row
- **Story cell** carries: story title, then `Size` (trivial / normal / risky), `Type` (Core = unit-testable without the game; Plugin = game-touching, evidence is User's in-game run plus the mod log), `Dep` (order numbers that must be Done first), `Inv` (invariants the card touches or must not break), `Par` (parallel-dispatch note).
- Plugin cards: criteria of the form `in-game:` (what User does, then what is observed) and `log:` (event lines expected in `<game>/BepInEx/ShelfTransfer/shelftransfer.log`, D5). The Overseer greps the log; undriveable legs are reported `manual test — confirm` (D9).
- Core cards: criteria are `unit:` tests run by the tester (D10).
- Risky = calls take/store on the host, starts a transfer, or enforces I1/I3/I4. Gets the full loop (dev, reviewer, security if flagged, tester, seer, end-to-end gate).
- Log catalogue additions this board assumes (Overseer to append to architecture.md F4 when card 1 lands): `ui.hint`, `ui.overlay`, `ui.label`, `transfer.request`, `transfer.cancel`. All use the same `key=value` format.
- Scaffold (solution, csproj, `ShelfKey` + 3 tests, gateway records, `IModLog` interface) already exists per architecture.md Structure; no setup card.
- Plugin composition: card 2 creates `ShelfTransferPlugin.Load` calling three feature installers (`Runtime/TransferFeature.cs`, `Labels/LabelsFeature.cs`, `Ui/UiFeature.cs`) and `ModConfig` with every entry up front. Later cards edit only their own installer, so phase 2 and phase 3 share no files.
- Parallel work touching git requires `isolation: "worktree"` (CLAUDE.md).
